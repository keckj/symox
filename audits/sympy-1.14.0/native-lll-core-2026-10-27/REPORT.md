Four native unit tests and an integration test covering 651 fixtures pass locally; core correctness clippy passes with no diagnostics in the new code. The fixtures cover 640 successful bases, 2 rank errors, 1 shape error and 8 invalid deltas, including empty/rectangular cases and 65/127/1024-bit integers. Exact transforms satisfy T*A=B and det(T)=±1; Gram–Schmidt, size-reduction and Lovasz certificates are independently recomputed with Python Fraction in the audit generator.

The expected algorithm uses floor(mu+1/2) exactly. The unmodified SymPy 1.14 path routes math.floor through binary64 for its ground QQ type. On 9 selected large-integer fixtures it raises 3 AssertionErrors or returns 6 different valid reduced bases. Both original outcomes and the exact-floor reference variant are retained in reference-fixtures.json; this is a disclosed arithmetic correction, not bitwise agreement with an incorrect floor. The first comparison failure against an unmodified large reference result is retained in initial-reference-floor-parity.log. Ordinary 631 successful fixtures agree unchanged.

The core keeps input immutable, returns distinct rank/shape/delta/interruption errors and records untouched-row origins for later publication of existing row objects; size-reduced rows have no source. No cap or approximate arithmetic is used by the kernel. This has no Python API/binding yet and is NOT integrated into main. The existing Python algorithm and general DomainElement math.floor gap remain in production pending a guarded public route. No performance or global parity claim follows.
