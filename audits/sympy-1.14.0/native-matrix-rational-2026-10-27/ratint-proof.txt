Native bounded ratint driver — 2026-10-27

SCOPE AND ARCHITECTURE
New Rust integrate/ratint_driver.rs orchestrates the established QQ/ZZ rational pipeline. Eligible inputs are exact canonical native expression nodes rational in a canonical commutative Symbol/Dummy x, or an exact two-element Python tuple of such polynomial nodes/exact Python ints. Python ints at top level deliberately refuse: the old public API raises AttributeError before sympification there. Tuple subclasses, generators, host classes, noncanonical variables, additional coefficients/variables, Float/RR, algebraic/EX/nonfinite data retain the old complete public body. Only real=None/True plus stock string/Symbol/Dummy auxiliary labels are ported. real=False and other truth-like/custom options retain the established full RootSum/logarithm path. Unknown flags remain ignored without inspecting their values, as before. There is no new top-level symox.ratint alias; the established public function is symox.integrals.rationaltools.ratint.

Seven source files: new driver and tests; module declaration; existing cancel_int helper made pub(crate) without an algorithm edit; log_to_real stored-polynomial adaptation extracted into rational_input and reused by its original binding and the driver; existing integration_methods binding/registration; a Python dispatch/protocol adapter. No mathematical algorithm was added in Python; the old driver body is intact. The native result carries an exact boolean telling whether the logarithmic branch was used. The adapter validates the corresponding callbacks before publishing it. Pure polynomial/rational results do not pay unrelated log/atan proofs. Any unsupported subproof discards the entire candidate and continues through the unchanged public body. No incomplete rational/atan/log sum or false absence of an integral is returned.

EXACT NORMALIZATION AND BRANCH REPRESENTATIVES
The driver invokes the SAME core as_numer_denom as the public expression method (simptools::as_numer_denom), not a newly written fraction splitter. Both first Poly values are over QQ, matching composite=False/field=True on closed rational coefficients. It reuses poly::api::cancel_int, already used by apart, for the reference dmp_cancel unit convention: integer cofactors, positive leading coefficients and a separate signed rational coefficient. If Dp,Dq clear the original coefficient denominators, the separated coefficient is Dq/Dp (with the cofactor sign), and the integer cofactor pair is jointly coprime with positive leading coefficients. This is the same normalized pair reconstructed by the public Poly.cancel binding. In particular the sign is not moved into a logarithm argument.
Polynomial division and polynomial integration call the existing Poly primitives. Horowitz–Ostrogradsky reduction calls the existing rational_reduction::reduce, including its exact identity certificate; both returned fractions pass through exactly the same poly::api::cancel as the existing ratpart binding. The logarithmic fraction uses the same as_numer_denom and natural Poly inference, then the same second division/integration. Nonzero remainder calls the existing signed logarithmic_reduction LRT engine. Each group uses the SAME public primitive convention (FractionPoly::reference_primitive, ground_primitive or Poly::primitive); the discarded content is never guessed or normalized differently. Stored polynomial adaptation is shared with the original log_to_real binding, so fraction-field legacy metadata is never mistaken for its real coefficients.
Only groups certified by the existing exact linear/quadratic log_to_real rule are accepted. Its root enumeration, positive-imaginary pairing and exact Euclidean atan representatives are reused without combining logarithms or arctangents. A higher-degree/degenerate group refuses the WHOLE driver, so the established complete RootSum/real conversion branch remains available. The final separated coefficient multiplies the complete sum exactly once. This same-pipeline proof fixes principal-branch constants; equal derivatives alone would not suffice. Tests include the whole-denominator log(x^2-1), negative units, repeated poles, mixed rational/log terms and the public degree-five example, plus exact real/complex pole specializations. Auxiliary Symbol.as_dummy drops its assumptions to a fresh Dummy of the same name in the old public code; the native path uses that same unnamed-assumption convention. Its auxiliary generator is fully eliminated on accepted groups.

PRE-AS_NUMER_DENOM RESOURCE PROOF
The initial version bounded each exponent but did not bound compounded powers before as_numer_denom. The FINAL driver instead computes conservative integer-polynomial bounds for a representation N/D at EVERY expression node, before numerator extraction or expansion, on both expression and tuple routes. A shape contains upper degrees n,d and integer coefficient bit bounds nb,db, with |coefficient|<2^bits. A rational literal starts with its exact numerator/denominator bit lengths, and x with degrees(1,0),bits(1,1). For polynomial product, each coefficient has at most min(degA,degB)+1 summands, so bits are bounded by bitsA+bitsB+ceil(log2(min(degA,degB)+1)). Rational sums use N1D2+N2D1 and D1D2, the two convolution bounds and one extra addition bit. For the k-th power, k*(bits+ceil(log2(degree+1))) bounds the coefficient magnitude, since it dominates k*bits+(k-1)*log2(degree+1); negative powers swap numerator/denominator bounds. All operations are checked integer arithmetic, never floating-point samples.
Every intermediate bound must have degrees<=32 and bits<=4096. A path has at most64 levels and4096 visited nodes. Thus nested bounded powers cannot hide a degree/bit explosion: refusal happens BEFORE the first as_numer_denom, including hidden exact numeric powers. Bounds deliberately overestimate cancellation and can refuse a smaller simplified result; that is only route selection, and the full public calculation remains available. A second polynomial preflight precedes Poly::from_expr and any dense conversion. The logarithmic rational expression returned by ratpart is also checked before its numerator extraction. Univariate degree32 bounds the expanded monomial count to33, and the per-node coefficient bounds protect the expansion arithmetic. Existing subkernels retain their own checked work/degree/coefficient limits; their refusal is never a partial result.
A new Rust regression constructs raw nested powers of32 with additions for both x+1 and the numeric constant2, keeping the witness itself unevaluated; the shape and complete driver refuse on expression and tuple routes. Python differential witnesses exceed the route degree with a degree64 nested polynomial and coefficient size with an8191-bit held numeric coefficient (8192-bit conservative bound); both still compute the identical complete public result and exact derivative. Sparse degree1,000,000 also refuses before expansion. These are bound/refusal tests, not claims that the full computations are unsupported.

PROTOCOLS AND ERRORS
The basic adapter checks canonical bootstrap/constructor/sympify functions, their actual code/closure/defaults, scalar numerator/construction metadata and the existing authenticated arithmetic/MRO/priority proof. Applicable int/object converters are inspected only for exact Python ints in an exact tuple; unrelated safe registrations do not disable stock dispatch, and native Expr inputs retain the public sympify fast path before converter lookup. It never iterates a user sequence while deciding eligibility. The binding checks stock Poly descriptors/methods used by the complete path, including presentation delegates, rather than silently bypassing real Poly overrides.
For a logarithmic result the adapter additionally checks the same resultant/as_poly/LRT and log_to_real/atan protocols. Native subkernel/public-helper replacements force the complete old path; the validators themselves have canonical identity/code/default checks before being called, preserving replacement callbacks exactly once. The registry's original Zero accumulator is guarded without executing arbitrary descriptors, so changing that representative to7 retains the old additive constant rather than silently replacing it by0. Metadata/protocol guards contain no mathematical loops or calculations of coefficients.
No host exception or KeyboardInterrupt is caught as a successful computation/refusal. Signals are checked at entry, around primitive calls, in HO/LRT/conversion loops and before a complete return. A Rust unit interrupts inside the pipeline and requires Err, never a partial answer. Held evaluate(False) remains entirely on the old body. Error messages/ordering, real=False, custom names/protocols, malformed tuples and unsupported domains are compared against that unchanged body. Scalar integer/sparse degree limits do not turn a full fallback into an absence proof.
