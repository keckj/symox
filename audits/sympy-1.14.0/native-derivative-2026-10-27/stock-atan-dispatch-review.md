# Stock Ore dispatch and native log_to_atan eligibility

The 66 log_to_atan route failures were reproduced through collection alone using the exact corrected-targeted input list. All arithmetic values still matched. Holonomic import installs an official Expr add/mul forwarding wrapper after rationaltools captures the initial operators. Identity-only comparison therefore disabled the native route. `diag-atan-collection.log` records the precise operator differences; no tests were run by this diagnostic.

The three-file package in `branches/log-atan-stock-dispatch` recognizes only an intact official forwarding layer for ordinary native scalar results. It validates installed object/record identities, the canonical wrapper code, closure name/delegate, callable closure chains, code/default/closure snapshots, globals and Ore class/MRO, plus ordinary scalar marker/attribute lookup. The original arithmetic delegate is independently anchored during package bootstrap. It does not trust wraps metadata. QQ/ZZ, degree limits, native kernel and complete old fallback remain unchanged.

User wrappers, mutated code/cells/delegates/globals, forged or malformed records, host generators, marker descriptors and scalar attribute hooks decline the route. Their original callbacks/errors remain observable. Actual Ore and Holonomic operands retain reflected dispatch. Standard rationaltools reload preserves bootstrap anchors. Recurrence reload or manually removing/reimporting rationaltools can conservatively use the old path; these states do not justify blessing a new arbitrary operator capture. The proof is an optimization selector, not a security boundary against arbitrary replacement of the Python interpreter or all private bootstrap anchors.
