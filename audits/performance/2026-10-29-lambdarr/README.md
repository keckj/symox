# lambdarr (wave 29): lambdify on float64 / complex128 arrays

Harness: `bench.py <label> <out.json> [filter]`. Each case runs in `BENCH_PROCS`
(default 3) fresh processes. "first" is `lambdify` plus the first call (imports
excluded), "repeat" is the median per-call time of 7 batches.

    # symox tree under test
    PYTHONPATH=<worktree>/python python bench.py after after.json
    # SymPy 1.14 reference, run from /tmp
    cd /tmp && BENCH_MODULE=sympy python <dir>/bench.py sympy sympy.json
    python table.py > table.md

Files: `sympy.json` (SymPy 1.14 + NumPy, same machine), `before.json` (base
581f7bb1), `after.json` (this branch), `table.md` (generated by `table.py`).
Data are `np.linspace(0.1, 2, n)` (complex: `+ 0.25j`), argument k scaled by
`1 + k/4`.

Notes:
- `after.json` was measured while the integration and ODE corpora were running
  on the same machine, so it is pessimistic. The scalar rows (`gamma_float`,
  `poly2_float`) did not change in code: an interleaved isolated
  microbenchmark gave before/after equal within noise (poly2 2.05-2.25e-7 s vs
  2.23-2.32e-7 s, gamma 6.05-6.37e-7 s vs 6.10-6.58e-7 s).
- gamma float64 stays about 200x slower than SciPy per element: the
  double-double `gamma_real` kernel (~1.9 us/element) is kept to preserve the
  established values bit for bit. It is a recorded gap, not a regression.
- complex128 calls go through the established NumPy object evaluator (the
  computation stays NumPy). Overhead on 10-element arrays is 1.1-1.2x SymPy.
- complex gamma used to raise AttributeError (no `numpy.gamma`); it now calls
  the generated function (SciPy), with the SymPy 1.14 value.
